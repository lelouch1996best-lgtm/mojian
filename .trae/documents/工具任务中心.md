# AI 小工具「任务中心」实施计划

## Summary

小工具页面的轮询与结果展示全部迁到独立的「任务中心」：

1. **服务端任务中心**（仿照现有 `lib/image-task-center.ts` 模式）：新表 `tool_tasks` + 单例轮询器 `lib/tool-task-center.ts`，任务提交后由 Next.js 服务端进程持续轮询上游（RunningHub / 本地 ComfyUI），页面关闭、刷新、重启（经 ensureRunning 惰性恢复）均不丢任务。
2. **小工具页面只负责"发起"**：上传 → 构建参数 → 提交上游 → 注册进任务中心，然后提示"去任务中心查看"。发起按钮防呆：提交期间禁用，成功/失败后 1 秒冷却再恢复，可连续发起多个任务。不再展示结果。
3. **任务中心页面** `/tools/tasks`：任务列表（状态筛选、自动刷新）、结果预览（图片/视频）、下载、取消、删除。

## Current State Analysis

- 5 个工具（super-resolution / outfit-change / image-inpaint / minimax-video / z-image）都在组件内 `handleStart` 中：上传 → `submitXxx()` → `pollRunningHubTask()` / `pollComfyUiPrompt()`（前端轮询）→ 页内展示结果。页面一关，轮询终止、结果丢失。
- 已有可复用的服务端轮询先例：`lib/image-task-center.ts`（单例挂 globalThis、`ensureRunning()` 惰性恢复、`image_tasks` 表、终态回填 `updateApiCallFinal`）。本计划完全照此模式。
- 提交链路已写 `api_call_logs`（`task_id` = 上游 taskId/promptId），轮询终态由前端 `finalizeApiCallLog` 回填——迁移后由服务端轮询循环调用 `updateApiCallFinal`（lib/api-call-logger.ts 已有）回填。
- 存储：better-sqlite3（`lib/db.ts` 的 `getDb()` 建表 + PRAGMA 迁移模式）。
- ComfyUI history 归一化逻辑目前内联在 `app/api/comfyui/history/route.ts`，服务端轮询需要复用 → 抽取为共享模块。
- RunningHub 查询：`POST https://www.runninghub.ai/openapi/v2/query`，apiKey 存 settings 表 key="runninghub"（服务端可直接读库）。
- 下载代理 `/api/runninghub/download?url=&name=` 是通用下载代理（ComfyUI `/view` 链接同样可用）。
- 工具页外壳：`components/tools/ToolPageShell.tsx`（头部有"返回"按钮）；工具列表 `app/tools/page.tsx`（头部有标题栏）——两处加「任务中心」入口。`app/tools/[id]/page.tsx` 是动态路由，`/tools/tasks` 静态路由优先级更高，不冲突。

## Proposed Changes

### 1. 数据库：`lib/db.ts`

在 `getDb()` 建表 SQL 末尾追加：

```sql
CREATE TABLE IF NOT EXISTS tool_tasks (
  id               TEXT PRIMARY KEY,      -- 本地任务 id（uuid）
  tool_id          TEXT NOT NULL,         -- 如 "z-image"
  tool_name        TEXT NOT NULL,         -- 如 "文生图片（Z-Image Turbo）"（日志「模型」字段同款）
  source           TEXT NOT NULL,         -- "runninghub" | "comfyui"
  media_type       TEXT NOT NULL,         -- "image" | "video"（结果文件挑选 + 预览方式）
  title            TEXT NOT NULL DEFAULT '',  -- 摘要（模式/倍率/时长/比例等，一行动态拼）
  prompt           TEXT NOT NULL DEFAULT '',  -- 展示用提示词（截断存储 500 字）
  upstream_task_id TEXT,                  -- RunningHub taskId / ComfyUI promptId
  base_url         TEXT,                  -- 仅 comfyui
  status           TEXT NOT NULL,         -- pending|running|done|failed|cancelled|expired
  result_url       TEXT,
  error            TEXT,
  fail_count       INTEGER NOT NULL DEFAULT 0,
  created_at       INTEGER NOT NULL,
  updated_at       INTEGER NOT NULL,
  completed_at     INTEGER
);
CREATE INDEX IF NOT EXISTS idx_tool_tasks_status ON tool_tasks(status);
CREATE INDEX IF NOT EXISTS idx_tool_tasks_created_at ON tool_tasks(created_at DESC);
```

### 2. 共享 history 归一化：新 `lib/comfyui-history.ts` + 改 `app/api/comfyui/history/route.ts`

- 从 history 路由中把「fetch 上游 `/history/{promptId}` + 归一化为 `{status, files, errorMessage}`（含 images/gifs/audio 文件、execution_error 提取）」抽成 `export async function fetchComfyUiHistory(baseUrl: string, promptId: string): Promise<ComfyUiHistoryResponse>`（内部含 10s 超时与错误抛出，错误信息与现状一致）。
- `app/api/comfyui/history/route.ts` 改为参数校验后直接调用该函数（行为不变，纯抽取）。

### 3. 服务端任务中心：新 `lib/tool-task-center.ts`

仿 `lib/image-task-center.ts`：

```ts
const POLL_INTERVAL = { comfyui: 4000, runninghub: 8000 };
const HARD_TIMEOUT = { comfyui: 30 * 60_000, runninghub: 15 * 60_000 };
const MAX_CONSECUTIVE_FAILURES = 10;   // 连续瞬态失败 → failed
const TERMINAL_RETENTION_MS = 7 * 24 * 3600_000; // 终态保留 7 天
```

- `class ToolTaskCenter`（挂 `globalThis.__toolTaskCenter`，防 HMR 重建）：
  - `registerTask(input)`：插入 `tool_tasks`（status="running"，因为注册时上游已受理），`startLoop(id)`，返回记录。幂等：同 `upstream_task_id` 已存在则直接返回。
  - `listTasks({ status?, limit, offset })`：降序分页 + total。
  - `cancelTask(id)`：stopLoop；comfyui 任务额外 `POST {baseUrl}/interrupt`（尽力而为）；置 status="cancelled"；`updateApiCallFinal(upstream_task_id, "failed", "已取消")`。
  - `deleteTasks(ids)`：stopLoop + DELETE。
  - `ensureRunning()`：节流 60s；清理 7 天前终态任务；扫描 pending/running 重启轮询循环。
  - `pollLoop(id, signal)`：
    - comfyui：`fetchComfyUiHistory(base_url, upstream_task_id)`；
    - runninghub：从 settings 表读 `runninghub.apiKey`，`POST https://www.runninghub.ai/openapi/v2/query`（Bearer），解析 `status/results[0].url/errorMessage`（QUEUED/RUNNING 继续轮询，SUCCESS→done，FAILED→failed）。
    - 结果挑选：comfyui 按 `media_type` 挑文件（video：`\.mp4|webm$` 优先，fallback files[0]；image：`\.png|jpe?g|webp$` 优先，fallback files[0]）存 `result_url`；runninghub 取 `results[0]?.url`。
    - 终态（done/failed/expired）时 `updateApiCallFinal(upstream_task_id, ...)` 回填日志（与 image-task-center 相同的三态映射）。
    - 瞬态失败计数 / 硬超时 expired，逻辑照抄 image-task-center。

### 4. API 路由

- 新 `app/api/tool-tasks/route.ts`：
  - `GET`（validateAuth）：`?status=&limit=&offset=`，调 `ensureRunning()` 后 `listTasks`，返回 `{ items, total }`（行转记录函数放 route 内，字段驼峰化，不含敏感信息）。
  - `POST`（validateAuth）：body `{ toolId, toolName, source, mediaType, title, prompt, upstreamTaskId, baseUrl? }`，校验必填后 `registerTask`，返回任务记录。
  - `DELETE`（validateAuth）：body `{ ids: string[] }`，`deleteTasks`。
- 新 `app/api/tool-tasks/[id]/cancel/route.ts`：`POST` → `cancelTask(id)`（进行中才可取消，终态返回 400）。

### 5. 类型与客户端：`lib/types.ts` + `lib/api-client.ts`

- types.ts 新增：

```ts
export type ToolTaskStatus = "running" | "done" | "failed" | "cancelled" | "expired";
export interface ToolTaskRecord {
  id: string; toolId: string; toolName: string;
  source: "runninghub" | "comfyui"; mediaType: "image" | "video";
  title: string; prompt: string; upstreamTaskId?: string; baseUrl?: string;
  status: ToolTaskStatus; resultUrl?: string; error?: string;
  createdAt: number; updatedAt: number; completedAt?: number;
}
export interface ToolTaskListResponse { items: ToolTaskRecord[]; total: number; }
export interface ToolTaskRegisterInput { /* 同 POST body */ }
```

- api-client.ts 增加方法：`listToolTasks(params)`、`registerToolTask(input)`、`cancelToolTask(id)`、`deleteToolTasks(ids)`（照 `listApiLogs` 等现有写法）。

### 6. 发起防呆 hook：新 `components/tools/useTaskSubmit.ts`

```ts
export function useTaskSubmit() {
  // submitting: 提交中；cooldown: 提交结束后的 1s 冷却
  // run(fn): 包装 async 提交函数；结束（无论成败）后 1000ms 解除禁用
  return { submitting, cooldown, disabled: submitting || cooldown, run };
}
```

组件用法：`disabled={!canStart || guard.disabled}`，提交中文案「提交中…」，冷却期同样禁用按钮（防连点）。

### 7. 任务中心页面：新 `app/tools/tasks/page.tsx`

- 路径 `/tools/tasks`（"use client"），头部：返回 `/tools`、标题「任务中心」。
- 状态筛选 pill：全部 / 进行中（running）/ 已完成（done）/ 失败（failed、cancelled、expired 归入"已结束"？——简化为：全部｜进行中｜已完成；失败/取消任务在"全部"里可见）。
- 列表加载：`apiClient.listToolTasks`；存在 running 任务时 `setInterval` 3s 自动刷新（GET 内部会 `ensureRunning` 惰性恢复轮询），无 running 时 15s 慢刷或停止。
- 任务卡片：工具名 + 来源徽标（复用 registry 的 SOURCE_LABELS 样式：local=绿、runninghub=蓝）+ 媒体类型 + title + prompt 摘要（line-clamp）+ 状态中文标签（排队/处理中=running，成功，失败，已取消，已超时）+ 耗时/时间 + 错误信息。
- 结果展示：`mediaType==="video"` 用 `<video controls>`，`"image"` 用 `<img>`（max-h 限制），下载按钮走 `/api/runninghub/download?url=…&name=…`。
- 操作：running 任务显示「取消」；所有任务显示「删除」；顶部支持批量清理已完成（DELETE 传已完成 ids，可选做，简单起见只做单条删除 + "清空已完成"一个按钮）。
- 空态文案：「暂无任务，去 AI 小工具发起一个吧」+ 跳 `/tools` 链接。

### 8. 五个工具组件改造（统一模式）

对 `SuperResolutionTool` / `OutfitChangeTool` / `ImageInpaintTool` / `MiniMaxVideoTool` / `ZImageTool`：

- `handleStart` 改为：**上传 → 构建参数 → submitXxx/submitComfyUiPrompt（保留 AbortController，可中断提交/421 重试等待）→ `apiClient.registerToolTask({...})` → 显示成功提示**。不再调用 `pollRunningHubTask` / `pollComfyUiPrompt`。
- 注册参数：
  - toolId/toolName 取 registry 中 id/name（或提交时的 logModel 同名值）；
  - runninghub 三件套：`source:"runninghub"`、`upstreamTaskId: run.taskId`、`mediaType` 按工具（超分=video，换装/局部编辑=image）；
  - comfyui 两件套：`source:"comfyui"`、`upstreamTaskId: run.promptId`、`baseUrl`；
  - title 动态拼（如超分「2x 超分」、换装「换装 · {prompt 前 20 字}」、minimax「{模式} · {秒数}s · {比例}」、z-image「{文生图/图生图} · {比例}」），prompt 存用户提示词。
- 用 `useTaskSubmit()` 包裹提交：按钮 `disabled={!canStart || guard.disabled}`，提交中显示「提交中…」+ 保留「取消」ghost 按钮（仅中断提交阶段）；结束 1s 后自动恢复。
- 提交成功后：清 error，显示成功条（emerald）「任务已提交，进度与结果请前往任务中心查看」+ Button 跳 `/tools/tasks`；失败显示 error 红条。**删除**结果展示区（video/img + 下载按钮 + "未解析到结果"提示）与轮询相关 stage/status 逻辑。
- 「开始新任务/重置」语义保留（minimax 上次已改为只清结果不清输入，继续沿用：只清提示消息/错误，输入保留）。
- MiniMaxVideoTool 的「释放内存」按钮、模型选择、ComfyUiConfig 等全部保留，仅去掉轮询/结果部分。
- 上传中 statusText（"正在上传…"）保留，轮询 status 文案删除。

### 9. 入口：`app/tools/page.tsx` + `components/tools/ToolPageShell.tsx`

- 两处 header 右侧各加一个按钮 `router.push("/tools/tasks")`「任务中心」（Button variant="secondary" size="sm"）。
- 不改 registry 结构（任务中心不是 ToolDefinition，是独立页面）。

## Assumptions & Decisions

1. **服务端轮询**（而非任务中心页面轮询）：用户痛点是"页面关闭任务丢失"，且项目已有 image-task-center 成熟先例；dev 重启后靠 GET 时 `ensureRunning()` 从 DB 恢复。
2. **提交仍在工具页前端完成**（复用现有 421 自动重试、动态拼图、上传逻辑，零改动），提交成功后注册进任务中心并启动服务端轮询。提交期间关页属极端场景，不做"提交前先落库"。
3. **取消语义**：ComfyUI 任务取消 = 停止轮询 + 调 `/interrupt` 中断本机执行；RunningHub 无上游取消 API，取消仅停止轮询并标记"已取消"（上游任务照跑，日志回填 failed/"已取消"）。
4. RunningHub 查询由服务端直接读 settings 表 apiKey 调上游，不经前端、不在任务记录中存 apiKey。
5. 旧 `api_call_logs` 日志链路不动：提交日志照旧写入，终态回填改由服务端轮询循环完成（`updateApiCallFinal`）。
6. 工具页不再有任何结果展示（含 RunningHub 24h 有效期提示），下载统一在任务中心。
7. 超时沿用现状：ComfyUI 30 分钟、RunningHub 15 分钟；终态任务保留 7 天后自动清理。

## Verification

1. `npx tsc --noEmit`（基线：qiniu 既有报错除外，无新增报错）。
2. 手动流程（RunningHub 换装）：发起 → 按钮"提交中…"禁用 → 成功提示 + 1s 后按钮恢复 → 连续发起第二个任务 → 关闭工具页 → 打开 `/tools/tasks` 两条任务均在轮询 → 完成后出现结果图 + 下载；日志页 final_status 已回填。
3. 手动流程（本地 z-image / minimax-video）：发起后关工具页，任务中心持续轮询 ComfyUI history；running 任务点「取消」→ ComfyUI 执行中断、任务标记已取消。
4. 页面刷新/重启 dev server 后打开任务中心，running 任务自动恢复轮询。
5. 防呆：提交期间重复点击按钮无效；成功/失败后 1 秒内按钮仍禁用。
