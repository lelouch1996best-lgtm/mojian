# 设定页（人物、物品、场景）详情弹框改造计划

## 一、概述

将人物、物品、场景三个设定页中当前在卡片内「展开/收起」的详情编辑区域，迁移到独立的弹框页面中。每个类型一个弹框组件，卡片上保留最常用的图片、名称、版本标签（人物再保留音色）的快捷编辑入口，同时移除卡片上的简短说明（红色部分）与「全部展开/全部收起」按钮。

人物弹框需要为后续「关系图谱 / 关联其他设定」预留扩展结构（标签页形式），物品和场景弹框保持基础字段弹框。

## 二、当前状态分析

- 三个设定页结构高度一致：
  - `app/series/[id]/characters/page.tsx` + `CharacterCard.tsx`
  - `app/series/[id]/objects/page.tsx` + `ObjectCard.tsx`
  - `app/series/[id]/scenes/page.tsx` + `SceneCard.tsx`
- 每个页面维护 `expandedIds` 状态，控制每张卡片的展开收起。
- 卡片内显示一个简短说明：
  - 人物：`genderAge`（截图中的红色框）
  - 物品：`category`
  - 场景：`category`
- 点击「展开详情」后，在卡片下方展示剩余字段表单（蓝色框）。
- 字段变更通过 `onUpdate` 实时同步到父级 state，并触发自动保存。
- 存在 `expandAll` / `collapseAll` 按钮。
- 项目已有通用弹框组件 `components/ui/Modal.tsx`（默认 `max-w-lg`）。

## 三、改造决策

| 问题 | 决策 |
|---|---|
| 弹框字段范围 | 弹框内包含完整字段（图片、名称、版本标签、所有详情字段、人物音色）；卡片上仍保留图片、名称、版本标签、音色的快捷编辑。 |
| 保存时机 | 继续沿用实时自动保存，弹框内字段修改通过同一 `onUpdate` 回调同步到父级 state。 |
| 弹框宽度 | `max-w-3xl`（768px），字段单列纵向排列。 |
| 入口文案 | 卡片上的「展开详情」改为「查看详情」。 |
| 人物弹框扩展 | 采用标签页：「基础信息」+ 「关联」（预留空标签页，后续填充关系图谱 / 关联设定）。 |
| 展开收起按钮 | 直接移除「全部展开 / 全部收起」按钮与相关状态。 |
| 简短说明 | 直接移除卡片上显示的 `genderAge` / `category` 简短说明。 |

## 四、具体改动

### 4.1 新建弹框组件

#### 1) `components/CharacterDetailModal.tsx`

- Props：
  - `character: CharacterProfile`
  - `open: boolean`
  - `onClose: () => void`
  - `onUpdate: (field: keyof CharacterProfile, value: string) => void`
  - `onGenerateImage: () => void`
  - `onUploadImage: (file: File) => void`
  - `isGenerating: boolean`
  - `isUploading: boolean`
  - `onRandomAppearance: () => void`
  - `onGenerateVoice: () => void`
  - `onAddVoiceFromAsset: () => void`
  - `onUploadVoice: (file: File) => void`
  - `onRemoveVoice: () => void`
  - `isGeneratingVoice: boolean`
  - `isUploadingVoice: boolean`
- 内部结构：
  - 标签页：「基础信息」|「关联」。
  - 「基础信息」页：顶部图片区（生成/上传/预览），名称、版本标签、音色条，下方依次排列角色定位、性别年龄、外貌（带随机生成 ✨）、性格、背景故事、人物关系。
  - 「关联」页：仅显示占位提示，例如「后续将支持关系图谱与关联其他设定」。
- 复用现有 `Modal` 组件，`width="max-w-3xl"`。
- 弹框内的图片、音色交互 UI 与现有卡片保持一致；音色播放器逻辑可直接从 `CharacterCard.tsx` 复制或稍后抽取公共 Hook（本次改造以复制最小改动为主，避免过度重构）。

#### 2) `components/ObjectDetailModal.tsx`

- Props：与 CharacterDetailModal 对称，去掉所有音色相关 props。
- 内部结构：单页布局，顶部图片区，名称、版本标签、分类、外观（带随机生成 ✨）、功能用途、来源背景。

#### 3) `components/SceneDetailModal.tsx`

- Props：与 ObjectDetailModal 类似。
- 内部结构：单页布局，顶部图片区（含粘贴 URL 功能），名称、版本标签、分类、外观描述（带随机生成 ✨）、光影氛围、来源背景。

### 4.2 修改卡片组件

#### `app/series/[id]/characters/CharacterCard.tsx`

- 移除 `expanded`、`onToggle` props。
- 移除卡片内 `genderAge` 简短说明的展示。
- 移除卡片内展开后的字段区域。
- 将「展开详情 / 收起详情」按钮改为「查看详情」，点击调用新增的 `onOpenDetail` 回调。
- 保留图片区、名称输入框、版本标签输入框、音色条。
- 新增 prop：`onOpenDetail: () => void`。

#### `app/series/[id]/objects/ObjectCard.tsx`

- 与人物卡片一致改造：移除展开相关 props 与 UI，移除 `category` 简短说明，按钮改为「查看详情」。

#### `app/series/[id]/scenes/SceneCard.tsx`

- 与物品卡片一致改造，同时保留图片区的「粘贴 URL」功能。

### 4.3 修改页面组件

#### `app/series/[id]/characters/page.tsx`

- 移除 `expandedIds` 状态、`toggleExpand`、`expandAll`、`collapseAll`。
- 新增状态：
  - `detailModalOpen: boolean`
  - `detailModalTargetId: string | null`
- 新增函数：
  - `openDetail(id: string)`：设置 targetId 并打开弹框。
  - `closeDetail()`：关闭弹框并清空 targetId。
- `handleAdd` / `handleAddVersion` 中原来 `setExpandedIds(...)` 的逻辑改为 `openDetail(newChar.id)` / `openDetail(newVersion.id)`，新增后自动打开详情弹框。
- 移除「全部展开 / 全部收起」按钮。
- `CharacterCard` 调用处：
  - 去掉 `expanded`、`onToggle`。
  - 新增 `onOpenDetail={() => openDetail(char.id)}`。
- 渲染 `CharacterDetailModal`：
  - `character={characters.find(c => c.id === detailModalTargetId)}`
  - `onUpdate={(field, value) => updateField(detailModalTargetId!, field, value)}`
  - 图片、音色相关回调复用已有 handler，通过 targetId 定位当前对象。

#### `app/series/[id]/objects/page.tsx`

- 与人物页面一致改造：移除展开相关状态与函数，新增 `detailModalOpen` / `detailModalTargetId`，新增/新建版本后自动打开弹框，渲染 `ObjectDetailModal`。

#### `app/series/[id]/scenes/page.tsx`

- 与物品页面一致改造，渲染 `SceneDetailModal`。

## 五、实现要点与风险

1. **数据流保持一致**：弹框与卡片共享同一个 `characters` / `objects` / `scenes` state，弹框内字段变更直接调用父级 `updateField`，自动保存逻辑无需改动。
2. **图片/音色回调的 targetId**：弹框打开时，`detailModalTargetId` 已确定，图片生成、上传、音色生成等回调可通过该 id 在父级 handler 中定位对象（或直接在 page 中写闭包）。
3. **人物弹框的音色播放器状态**：`CharacterDetailModal` 内部需要维护自己的 audio ref 和播放状态（与 `CharacterCard` 相同），退出弹框时自动释放。
4. **新增后自动打开弹框**：`handleAdd` / `handleAddVersion` 需要在 state 更新后再打开弹框。由于 React state 更新是异步的，可以使用 `setTimeout(..., 0)` 或直接在生成 new id 后调用 `openDetail(newId)`（`setCharacters` 传入函数式更新，new id 已知）。
5. **弹框内字段样式**：复用现有卡片内 `.char-input` / `.obj-input` / `.scene-input` 样式类，或改用 Tailwind 原生类，保持视觉一致。
6. **空状态**：无数据时的提示文案不变。

## 六、验证步骤

1. 进入人物设定页：
   - 确认卡片上不再显示「男，约25岁」等简短说明。
   - 确认「查看详情」按钮存在，点击后打开 `max-w-3xl` 弹框。
   - 确认弹框内可编辑所有字段，修改后触发自动保存。
   - 确认弹框内有「基础信息」和「关联」两个标签页。
   - 确认新增人物/新建版本后自动打开详情弹框。
   - 确认图片生成、上传、音色生成/上传/移除功能在弹框内可用。
2. 进入物品设定页：
   - 确认卡片上不再显示分类简短说明。
   - 确认「查看详情」打开物品详情弹框，字段正确。
3. 进入场景设定页：
   - 确认卡片上不再显示分类简短说明。
   - 确认「查看详情」打开场景详情弹框，字段正确，粘贴 URL 功能正常。
4. 通用检查：
   - 三个页面均无「全部展开 / 全部收起」按钮。
   - 自动保存提示正常出现。
   - 无 TypeScript 类型错误，可正常 `npm run build`（或项目对应构建命令）。
