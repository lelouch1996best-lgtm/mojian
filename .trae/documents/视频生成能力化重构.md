# 视频生成能力化重构计划

## 一、Summary（摘要）

将视频生成从「全局一套参数」改为「每个镜头卡片独立选模型 + 按模型能力动态配置参数」。核心是引入**模型能力描述（capability descriptor）**驱动 UI：选 Seedance 2.0 才出现「多模态参考」生成模式与视频/音频参考上传；分辨率/时长/宽高比的可选项随模型变化；全局设置仅保留 `apiKey` + `baseURL`（及模型列表管理）。

文档依据：火山引擎 Seedance 创建视频任务 API（`/docs/82379/1520757`）的「模型能力」章节。

## 二、Current State Analysis（现状分析）

### 现有架构 =「全局配置 + 卡片触发」
- **配置层** [SettingsModal.tsx#L673-786](file:///Users/hehuajiu/Workbuddy/mojian/components/SettingsModal.tsx#L673-786)：集中管理 `apiKey/baseURL/model/resolution/ratio/duration/watermark/generateAudio` 8 个字段，存于服务端 `settings.video`。
- **客户端层** [video-client.ts#L51-64](file:///Users/hehuajiu/Workbuddy/mojian/lib/video-client.ts#L51-64)：`createVideoTask(prompt, imageUrls)` 仅接收 prompt 与图片，其余参数全部从 `getVideoSettings()` 全局读取。

- **API 层** [app/api/video/create/route.ts#L24-47](file:///Users/hehuajiu/Workbuddy/mojian/app/api/video/create/route.ts#L24-47)：固定把第一张图作 `first_frame`、其余作 `reference_image`，无法表达「首尾帧」「多模态参考（含视频/音频）」等模式。
- **类型** [types.ts#L266-291](file:///Users/hehuajiu/Workbuddy/mojian/lib/types.ts#L266-291)：`VideoGenSettings` 含全部参数；`VideoCreateProxyRequest` 只有扁平 `imageUrls`。

### 痛点
1. 不同模型能力差异大（2.0 支持多模态参考、有声；1.0 Pro Fast 不支持首尾帧/1080p/有声），全局一套参数无法适配。
2. 卡片无法选模型，所有镜头只能用同一模型同一参数。
3. 全局配置混入生成参数，与「API 凭据」职责不清。

## 三、模型能力矩阵（核心依据，来自官方文档）

| 模型 | value | 生成模式 | 分辨率 | 时长(秒) | 宽高比 | 有声 | 多模态参考(图/视频/音频) | Draft |
|---|---|---|---|---|---|---|---|---|
| Seedance 2.0 | `doubao-seedance-2-0-260128` | 文生/首帧/首尾帧/**多模态参考** | 480/720/1080 | [4,15] 或 -1 | 全部含 adaptive | ✓ | ✓ 图0-9 视频0-3 音频0-3 | ✗ |
| Seedance 2.0 fast | `doubao-seedance-2-0-fast-260128` | 文生/首帧/首尾帧/**多模态参考** | 480/720 | [4,15] 或 -1 | 全部 | ✓ | ✓ | ✗ |
| Seedance 1.5 Pro | `doubao-seedance-1-5-pro-250428` | 文生/首帧/首尾帧 | 480/720/1080 | [4,12] 或 -1 | 全部含 adaptive | ✓ | ✗ | ✓ Draft |
| Seedance 1.0 Pro | `doubao-seedance-1-0-pro-250328` | 文生/首帧/首尾帧 | 480/720/1080 | [2,12] | 全部 | ✗ | ✗ | ✗ |
| Seedance 1.0 Pro Fast | `doubao-seedance-1-0-pro-fast-250328` | 文生/首帧 | 480/720 | [2,12] | 全部 | ✗ | ✗ | ✗ |

**生成模式（决定输入与 content 数组结构）**：
- `text2video`（文生视频）：仅文本
- `first-frame`（图生视频-首帧）：文本 + 1 张首帧图（role=`first_frame`）
- `first-last-frame`（图生视频-首尾帧）：文本 + 首帧图 + 尾帧图（role=`first_frame` + `last_frame`）
- `multimodal-ref`（多模态参考生视频）：**仅 2.0 系列**，参考图(0-9, role=`reference_image`) + 可选参考视频(0-3, type=`video_url`) + 可选参考音频(0-3, type=`audio_url`) + 文本（音频不可单独输入，至少 1 个图/视频）

### 改动 4：API 路由 — [app/api/video/create/route.ts](file:///Users/hehuajiu/Workbuddy/mojian/app/api/video/create/route.ts)

按 `mode` 构建 `content` 数组：
```typescript
const content: Array<Record<string, unknown>> = [{ type: "text", text: body.prompt }];

if (body.mode === "first-frame" && body.firstFrameUrl) {
  content.push({ type:"image_url", image_url:{url:body.firstFrameUrl}, role:"first_frame" });
} else if (body.mode === "first-last-frame") {
  if (body.firstFrameUrl) content.push({ type:"image_url", image_url:{url:body.firstFrameUrl}, role:"first_frame" });
  if (body.lastFrameUrl)  content.push({ type:"image_url", image_url:{url:body.lastFrameUrl},  role:"last_frame"  });

  (body.referenceImageUrls ?? []).forEach(u => content.push({ type:"image_url", image_url:{url:u}, role:"reference_image" }));
  (body.referenceVideoUrls ?? []).forEach(u => content.push({ type:"video_url", video_url:{url:u} }));
  (body.referenceAudioUrls ?? []).forEach(u => content.push({ type:"audio_url", audio_url:{url:u} }));
}
// text2video：不加任何素材
```

## 五、Assumptions & Decisions（假设与决策）

1. **范围**：仅重构视频生成；图片生成保持现状（用户已确认）。
2. **多模态参考**：完整支持参考视频/音频上传（用户已确认），走 COS 公网 URL。
3. **卡片默认值**：硬编码 `DEFAULT_SHOT_VIDEO_CONFIG`（Seedance 2.0 / first-frame / 720p / 16:9 / 5s / 无水印 / 无声），全局设置不再存生成参数（用户已确认）。
4. **迁移**：旧镜头无 `videoConfig` → 运行时回退默认，无需数据迁移；用户首次在卡片改参数时才落库 `shot.videoConfig`（惰性写入）。
5. **自定义模型能力**：未在 `VIDEO_MODEL_CAPABILITIES` 注册的模型用 `FALLBACK_CAPABILITY`（1.0 Pro 级、无多模态/有声）。
6. **首帧来源**：`first-frame`/`first-last-frame` 的首帧取关联资产第 1 张图（沿用现有「关联资产」机制）；尾帧走卡片上传 `lastFrameImageUrl`。
7. **生成模式默认**：`first-frame`（多数镜头已通过 @ 关联资产），无图时 UI 给出提示而非阻断。
8. **Draft 样片模式**：本期仅保留能力标记，不实现 Draft 交互（1.5 Pro 独有，逻辑较重，留作后续）。

## 六、Verification（验证步骤）

1. **类型检查**：`npx tsc --noEmit` 通过（VideoGenSettings 收窄后无残留引用）。
2. **全局设置**：打开 SettingsModal，视频区只剩 Base URL / API Key / 模型列表管理；保存后 `settings.video` 仅含两字段。
3. **卡片模型切换**：在 VideoCard 选 2.0 → 出现「多模态参考」模式 + 视频/音频上传；选 1.0 Pro Fast → 模式仅剩「文生/首帧」，分辨率仅 480/720，无声选项消失，时长 min/max=2-12。
4. **兼容收敛**：从 2.0(1080p) 切到 2.0 fast → resolution 自动回落 720p；从 1.5 Pro(adaptive) 切 1.0 Pro → ratio 回落 16:9。
5. **首尾帧**：first-last-frame 模式上传尾帧 → 生成请求 content 含 `first_frame`+`last_frame`。
6. **多模态参考**：2.0 + multimodal-ref + 上传 1 视频 1 音频 → 请求 content 含 `video_url`+`audio_url`+`reference_image`。
7. **非 2.0 拒绝多模态**：选 1.0 Pro 时模式无「多模态参考」选项。
8. **回归**：text2video 模式无图也能生成；首帧模式缺图时给错误提示而非崩溃。
9. **COS 上传**：上传 mp4/m4a 返回正确 ContentType 与可公网访问 URL。
