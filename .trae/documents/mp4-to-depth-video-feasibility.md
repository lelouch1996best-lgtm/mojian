# 将 MP4 视频制作成深度图视频的可行性评估

## 1. 摘要

用户希望了解「能否把普通 MP4 视频转换成深度图视频（depth map video）」。

结论：**技术上可行，但当前 Mojian 代码库和所依赖的 Seedance / APIMart 视频生成 API 均不提供原生深度图输出能力**。若要在产品内实现，需要引入独立的深度估计模型或第三方深度估计服务，而不是通过现有视频生成接口直接得到。

本报告基于当前代码库现状，给出三条可行路径，并从「能否复用现有基础设施、精度效果、成本资源、落地复杂度」四个维度进行对比。

## 2. 当前状态分析

### 2.1 现有视频生成能力

Mojian 当前的视频生成功能集中在：

- 前端：`/components/VideoGeneration.tsx` —— 镜头级视频生成 UI、配置面板、任务轮询。
- 客户端：`/lib/video-client.ts` —— 构造上游请求、创建/查询/取消任务。
- 服务端：`/app/api/video/create/route.ts`、`/app/api/video/query/route.ts` —— 透传火山方舟 / APIMart 视频生成接口。
- 类型定义：`/lib/types.ts` 中 `VideoGenerationMode` 支持：
  - `text2video`（文生视频）
  - `first-frame`（图生视频-首帧）
  - `first-last-frame`（图生视频-首尾帧）
  - `multimodal-ref`（多模态参考生视频，仅 Seedance 2.0）

参考视频输入仅在 `multimodal-ref` 模式下支持，且角色固定为 `reference_video`，作用是作为生成新视频的风格/内容参考，**不会返回任何深度信息**。详见 `/docs/video.md` 与 `/docs/APIMart/seedance2.0.md` 对 `video_url` 参数的说明。

### 2.2 深度/3D 相关现状

在代码库中搜索 `depth|深度|3D|stereo|disparity|景深|立体` 等关键词，没有发现专门处理深度估计、深度图生成或立体视频的功能、模型参数或 UI 入口。

因此：

- **Seedance / APIMart 视频模型本身**：不支持输出深度图视频。
- **Mojian 当前架构**：没有深度估计模块，也没有对应的数据类型和存储字段。

## 3. 可行方案对比

| 方案 | 核心思路 | 能否复用 Mojian 基础设施 | 精度/效果 | 成本/资源 | 落地复杂度 | 适用场景 |
|---|---|---|---|---|---|---|
| A. 调用第三方深度估计 API | 将 mp4 拆帧或切片，调用 Replicate / 阿里云视觉智能 / Stability 等深度估计接口，再合成为视频 | 可复用文件上传、COS 转存、任务中心；需新增深度任务类型 | 中等~高，取决于服务商模型 | 按量付费，适合低频/探索 | 低（新增一条 API 代理链路） | 快速验证、不想维护本地模型 |
| B. 本地运行深度估计模型 | 使用 Depth Anything V2 / MiDaS / ZoeDepth 等模型，在本地 GPU 或 CPU 上逐帧推理 | 文件上传可复用；推理部分需新增 Python/ONNX 服务或 Electron 原生模块 | 高（开源 SOTA），可做时序后处理稳定 | 一次性硬件/部署成本；后续几乎无调用费用 | 中~高（环境依赖、模型下载、跨平台打包） | 大量处理、对隐私/成本敏感 |
| C. 用 Seedance prompt 诱导生成 | 在多模态参考模式下，写 prompt 要求模型生成「深度图风格」的视频 | 完全复用现有视频生成流程 | 不可控，不是真正的深度图，深度值没有物理意义 | 和普通视频生成相同 | 最低 | 仅能做风格化演示，不推荐 |

### 3.1 方案 A：调用第三方深度估计 API

**代表服务**

- Replicate 上的 `depth-anything/depth-anything-v2` 或类似模型；
- 阿里云视觉智能「深度估计」相关能力；
- 部分云厂商提供的视频深度估计 API（需具体确认）。

**接入思路**

1. 用户在 Mojian 内上传 mp4（复用现有 `uploadRefFile` / COS 上传链路）；
2. 后端或前端将视频按帧拆成图片序列（可用 `ffmpeg`）；
3. 调用深度估计 API 得到每帧深度图；
4. 使用 `ffmpeg` 将深度图序列重新编码为 mp4 或导出为图片序列；
5. 结果写入 COS 并记录到任务中心（可复用 `/lib/image-task-center.ts` 的异步任务模式）。

**优点**

- 不需要本地 GPU；
- 模型选择灵活，可快速替换；
- 和当前「上传 → 异步任务 → 查询 → 下载」的架构契合。

**缺点**

- 按帧/按视频时长计费，长视频成本高；
- 网络往返多，长视频需要切片或批量处理；
- 需要单独处理时序一致性（相邻帧深度跳变）。

### 3.2 方案 B：本地运行深度估计模型

**代表模型**

- **Depth Anything V2**（2024，效果与泛化性较好）；
- **MiDaS**（成熟、模型小）；
- **ZoeDepth**（绝对深度估计，带尺度信息）。

**接入思路**

1. 在 Electron 主进程或独立 Python 服务中集成模型；
2. 用户上传 mp4 后，本地拆帧 → 模型推理 → 合成深度视频；
3. 结果可上传到 COS，也可仅保存在本地；
4. 对 Mojian 主流程侵入较小，可作为一个新的「本地工具」或「任务类型」。

**优点**

- 无 API 调用费用；
- 可自由做时序滤波、边缘对齐、分辨率自定义；
- 隐私性好，素材不出本地。

**缺点**

- 需要用户有 NVIDIA GPU 才能达到可用速度；
- 模型文件大，打包分发复杂；
- 跨平台（Windows/macOS）维护成本高；
- 需要处理 CUDA / ONNX Runtime / Core ML 等推理后端。

### 3.3 方案 C：用 Seedance prompt 诱导生成

**思路**

在 `multimodal-ref` 模式下，把 mp4 作为 `reference_video`，prompt 写「生成同一场景的深度图/depth map video，灰度表示远近」。

**结论**

不推荐。Seedance 是生成模型，不会输出像素级准确的深度关系；结果可能只是「看起来像深度图」的 RGB 视频，无法用于后续 3D 重建、景深合成等专业用途。

## 4. 推荐方案

如果目标是**在 Mojian 内快速、可控地提供「mp4 → 深度图视频」能力**，推荐：

> **方案 A（调用第三方深度估计 API）作为 MVP，方案 B（本地模型）作为后续降本增效的可选项。**

理由：

1. 和当前异步任务架构最匹配，前端只需新增一个「深度视频」任务卡片，后端新增 `/api/depth/create`、`/api/depth/query`；
2. 不需要改造 Electron 打包、GPU 环境等重基础设施；
3. 初期可以用 Replicate 等按需付费服务验证用户价值，确认需求后再评估是否投入本地模型。

如果目标是**离线、批量化、低成本处理**，则方案 B 更合适，但需要单独评估 Electron 本地推理的工程投入。

## 5. 假设与决策

| 假设/决策 | 说明 |
|---|---|
| 深度视频定义 | 每帧为单通道灰度深度图，白色表示近、黑色表示远；输出格式优先 mp4，也可提供 png 序列下载。 |
| 不依赖 Seedance 原生能力 | Seedance 及 APIMart 视频模型均无深度图输出参数，因此必须引入外部深度估计能力。 |
| 输入视频先转码为图片序列 | 当前主流深度估计模型以单帧图片为输入，需要在服务端或本地用 ffmpeg 拆帧/合成。 |
| 时序稳定性需后处理 | 单帧深度估计容易出现帧间闪烁，真正可用时需要加入时序一致性滤波（如光流约束、滑动平均）。 |
| 初步不追求绝对深度尺度 | 先输出相对深度图（灰度图）；如需绝对深度（米级），需使用 ZoeDepth 等支持绝对深度的模型并额外标定。 |

## 6. 验证步骤（若后续决定实施）

1. **POC 验证**：任选一段 5 秒 720p mp4，用 Replicate Depth Anything V2 API 拆帧 → 推理 → 合成 mp4，检查深度图质量和闪烁程度。
2. **成本测算**：按 720p/24fps 计算 1 分钟视频的处理费用和耗时的量级。
3. **架构验证**：在 `/app/api` 下新增 `/depth/create`、`/depth/query` 路由，复用现有 `api-call-logger.ts` 记录调用日志，确认任务恢复、错误处理链路可行。
4. **UI 验证**：在 `VideoGeneration.tsx` 或新增页面中放置「生成深度视频」入口，确认上传、轮询、结果展示流程可复用。

## 7. 风险与限制

- **模型限制**：深度估计模型对透明物体、镜面反射、低纹理区域、快速运动通常效果不佳。
- **长视频限制**：无论 API 还是本地模型，长视频都需要拆帧分批处理，存储和内存占用随分辨率、时长线性增长。
- **输出格式兼容性**：灰度 mp4 在某些播放器/编辑器中可能被当作 YUV 视频处理，需确认用户下游工具是否需要原始 png/exr 序列。
- **Seedance 参考视频 ≠ 深度视频**：不要误以为把 mp4 作为参考视频就能得到深度图。

## 8. 结论

**可以把 MP4 制作成深度图视频，但不能通过当前 Mojian 内置的视频生成模型直接完成。**

若要在产品内落地，建议：

- 短期：接入第三方深度估计 API（方案 A），复用现有异步任务和存储链路；
- 长期：根据使用量和成本，评估是否引入本地 Depth Anything V2 / MiDaS 推理（方案 B）。
