## 修复 server 模式下 series 缺 characterSettings 字段报错
- **问题**：server 模式下 `getSeries` 走 `apiClient.getSeries` 直接返回数据库 JSON，旧数据没有 `characterSettings` 字段，导致 `app/episode/[id]/page.tsx` 第 127 行 `seriesData.characterSettings.map` 报错。
- **根因**：`safeReadSeries` 的字段迁移逻辑只在 local 模式生效，server 模式没有对应处理。
- **修复**：`lib/storage.ts` 提取 `normalizeSeries(s)` 公开函数（补全 worldSettings/characterSettings/styleSettings/episodeOrder/order），在 `getSeries` 和 `listSeries` 的 server 分支返回前统一调用。
- 同时在 `handleCharactersExtracted` 中加 `?? []` 防御性兜底。

## 修复 server 模式下 characterSettings 无法持久化（提取人物设定后数据丢失）
- **问题**：点击「提取人物设定」后 LLM 正常返回 JSON，但人物设定页面无数据。
- **根因**：server 模式下 series 存储完全缺失 `character_settings` 字段——DB 表无此列、POST route 不写入、GET route 不读出。`saveSeries` 时 `characterSettings` 被静默丢弃。
- **修复**（3 个文件）：
  - `lib/db.ts`：series 建表 SQL 加 `character_settings TEXT NOT NULL DEFAULT '[]'` 列；加迁移逻辑 `try { SELECT character_settings } catch { ALTER TABLE ADD COLUMN }` 兼容旧库。
  - `app/api/data/series/route.ts`：POST 的 INSERT/UPDATE 加 `character_settings` 字段；`rowToSeries` 加 `characterSettings: safeParse(row.character_settings, [])`。
  - `app/api/data/series/[id]/route.ts`：GET 的返回加 `characterSettings: safeParse(row.character_settings, [])`。
- **注意**：DB schema 改动需重启 dev server 才生效（`getDb()` 缓存连接，迁移只在首次调用执行）。
- **调试辅助**：`ContentExpansion.handleExtractCharacters` 加了 console.log 打印 LLM 原始返回和解析结果；`handleCharactersExtracted` 加了 alert 成功提示。
